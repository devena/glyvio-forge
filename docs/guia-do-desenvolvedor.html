Um guia de referência para programadores sobre a arquitetura em três camadas, os padrões de código de cada camada, e como usar as skills e agentes de IA para acelerar o desenvolvimento.

⬡ plugin/app ⬡ plugin/server ⬡ plugin/environment ⬡ shared/commons
Arquitetura

Visão Geral do Sistema

Um plugin Glyvio é um monorepo dividido em quatro pacotes independentes, cada um com seu próprio ciclo de build via Webpack. Os três pacotes principais — app, server e environment — representam camadas que rodam em contextos completamente diferentes, mas compartilham tipos via shared/commons.

App

Frontend bundled pelo Webpack. Executa no browser/webview do usuário final. Responsável por telas, modais, filtros, menus e extensões de views existentes do CRM.

plugin/app/src/
Server

Lógica de negócio server-side. Interceptors que rodam antes/depois de salvar entidades no banco, controllers HTTP, e strategies de processamento.

plugin/server/src/
Environment

Integração com IA (Jeannie). System tools e custom tools que o agente de IA pode invocar. Services com acesso ao banco via SyncClient.

plugin/environment/src/
Shared

Constantes e tipos compartilhados entre camadas: PLUGIN_ID, PLUGIN_NAME, VERSION. Nunca contém lógica de negócio.

shared/commons/src/
Tipos via @types
Cada camada tem uma pasta @types/ com arquivos .d.ts gerados (glyvio_core.d.ts, entity.d.ts, permissions.d.ts, etc.). Esses são os contratos de API — nunca os edite manualmente. O TypeScript os lê automaticamente via o tsconfig do workspace.
Processo

Jornada Completa de uma Feature

Do requisito ao deploy, toda feature passa por etapas previsíveis. Abaixo o fluxo completo com as decisões e artefatos envolvidos em cada etapa.

Validações, side effects

Ferramentas de IA

Build & Release
Lint, build, versão
  1. Definir o Manifesto
    Se a feature precisa de um novo tipo de entidade, adicione a definição em manifest.json dentro de dbVersions (nova versão). Defina os campos, tipos, chaves estrangeiras e permissões necessárias. Use a skill /modify-manifest para guia interativo. Execute run_helper.sh após editar o manifesto para regenerar os tipos.
  2. Criar a tela no App
    Escolha o tipo de view: ListPage, TablePage, EditModal, EntityModal, etc. Use a skill correspondente (ex: /create-list-page). Registre a rota em plugin/app/src/index.ts. Se for estender uma tela existente, crie um interceptor de app com /create-list-page-interceptor.
  3. Adicionar lógica no Server
    Crie um BeforeInterceptor para validações que devem impedir o save, ou um AfterInterceptor para side effects (notificações, timelines, denormalizações). Use as skills /create-before-interceptor ou /create-after-interceptor. Os interceptors são descobertos automaticamente — não precisa registrá-los em index.ts.
  4. Expor para a IA (opcional)
    Se a feature deve ser acessível ao agente Jeannie, crie um SystemTool na camada environment com a skill /create-system-tool. Crie services com a lógica de acesso a dados usando o SyncClient auto-gerado. Tools também são descobertas automaticamente via decoradores.
  5. Build e Release
    Rode pnpm lint para checar TypeScript. Execute pnpm build para compilar todas as camadas. Use a skill /release-project para bump de versão, commit automático e push. O CI no GitHub Actions valida o build antes do deploy.
App Camada Frontend plugin/app/src/

Tudo que o usuário vê e interage. Compilado como bundle CommonJS pelo Webpack e injetado na interface do Glyvio. Nenhuma chamada direta à API — toda comunicação passa pelo glyvio_core.

Interceptors de App

Estendem views existentes do CRM (ex: ClientEditModal) para injetar campos, botões ou comportamentos extras.

extends/*.ts

Padrão de um EditModal

import * as glyvio_core from 'glyvio_core';

interface ErpState extends glyvio_core.SimpleEditModalState {
  name: string;
}

export class ErpEditModal extends glyvio_core.SimpleEditModal<ErpState> {

  initState(): ErpState {
    return { name: '', ...this.getDefaultState() };
  }

  getDesign(): glyvio_core.Design {
    return new glyvio_core.FormSectionDesign({
      children: [
        new glyvio_core.FormLayoutFieldDesign({
          label: 'Nome',
          design: new glyvio_core.StringTextfieldDesign({
            value: this.state.name,
            onChanged: (v) => this.setState({ name: v }),
          }),
        }),
      ],
    });
  }

  async onSave() {
    await glyvio_core.entityService.save('erp', { name: this.state.name });
  }
}
Atenção — Instanciação de Entidades
Sempre use await glyvio_entity.Erp.new() para criar instâncias de entidade. Nunca use new glyvio_entity.Erp() — o construtor direto não inicializa corretamente o estado interno do framework.

QueryBuilder — Padrão de Consultas

populateQueryBuilder(qb: QueryBuilder) {
  qb.addFilterOperator('name', 'LIKE', this.state.search);
  qb.addOrderByEntity('name', 'ASC');
  qb.addLeftJoinEntity('client');   // join com entidade relacionada

  // ⚠ use o caminho unido, nunca o ID direto
  qb.addFilterOperator('client.status', '=', STATUS_ACTIVE);
}
Regra de Paths
Em interpolações de design, use sempre item.client.name e nunca item.clientId. O Glyvio resolve os objetos joined — o ID direto não está disponível nos campos de display.
Server Camada Backend plugin/server/src/

Lógica executada no servidor Glyvio. Interceptors são descobertos automaticamente pelo Webpack — sem registro manual. Cada arquivo de interceptor usa decoradores que o framework lê em runtime.

BeforeInterceptor — Validações Pré-Save

Executa antes do dado ser gravado. Pode modificar o valor ou lançar um GlyvioError para cancelar o save e exibir mensagem ao usuário.

@glyvio_core.BeforeInterceptor({ entity: 'sale', id: 'sale-minimum-value' })
export class SaleMinimumValueInterceptor
  extends glyvio_core.SimpleBeforeInterceptor<glyvio_entity.Sale> {

  async handleBefore(value: glyvio_entity.Sale, ctx: Context) {
    if (value.totalValue < 100) {
      throw new glyvio_core.GlyvioError('Valor mínimo de R$ 100,00');
    }
    return value; // retornar o valor (possivelmente modificado)
  }
}

AfterInterceptor — Side Effects Pós-Save

Executa após commit no banco. Não pode cancelar — use para notificações, audit trail, denormalizações. Acessa o estado anterior via ctx.previousValue.

@glyvio_core.AfterInterceptor({ entity: 'client', id: 'client-notify-deleted' })
export class ClientNotifyDeletedInterceptor
  extends glyvio_core.SimpleAfterInterceptor<glyvio_entity.Client> {

  async handleAfter(value: glyvio_entity.Client, ctx: Context) {
    if (!value.deletedAt) return;  // só quando deletado

    await crm.GenerateNotificationStrategy.pushToQueue({
      entityId: value.id,
      message: `Cliente ${value.name} foi removido`,
    });
  }
}

AfterCommitInterceptor — Após Commit Durável

Semelhante ao AfterInterceptor, mas garante que a transação já foi commitada de forma durável antes de executar. Ideal para webhooks, filas externas e emails.

Controller — Endpoints HTTP

@glyvio_core.Controller({ path: '/visit-report', allowPrivateAccess: true })
export class VisitReportController
  extends glyvio_core.SimpleController<Request, Response> {

  async handle(req: Request): Promise<Response> {
    const visits = await glyvio_core.queryService.find('visit', {
      where: { userId: req.userId }
    });
    return { html: renderReport(visits) };
  }
}
Descoberta Automática
Interceptors e controllers não precisam ser importados em index.ts. O Webpack usa entry points glob (src/interceptors/**/*.ts) para descobri-los — o decorador registra a classe no runtime do framework automaticamente.

constants.ts — UUIDs de Negócio

Centraliza todos os UUIDs de status, grupos de usuário e tipos de entidade. Sempre importe daqui — nunca hardcode UUIDs inline:

// plugin/server/src/constants.ts
export const SALE_STATUS = {
  PROPOSAL:    'uuid-proposta',
  NEGOTIATION: 'uuid-negociacao',
  ACTIVE:      'uuid-ativo',
} as const;
Environment Camada IA / Ambiente plugin/environment/src/

Expõe funcionalidades do plugin para o agente de IA Jeannie. Tools são descobertas automaticamente via decoradores — sem registro manual. O acesso ao banco é feito através do SyncClient, um cliente RPC auto-gerado em service.ts (nunca edite esse arquivo).

SystemTool — Ferramenta para o Agente

@glyvio_core.SystemTool({
  id: 'devena-daily-briefing',
  permission: Permissions.TOOL_DAILY_BRIEFING,
  description: 'Retorna o briefing diário do usuário: tarefas, chats pendentes e vendas paradas',
})
export class DailyBriefingTool implements glyvio_core.CoreSystemTool {
  async handle() {
    const userId = glyvio_core.getContext().loggedUserId;
    const [tasks, chats, sales] = await Promise.all([
      TaskService.getInstance().fetchToday(userId),
      ChatService.getInstance().fetchPending(userId),
      SaleService.getInstance().fetchStalled(userId),
    ]);
    return formatMarkdown({ tasks, chats, sales });
  }
}

Services — Acesso a Dados (Singleton)

export class ChatService extends BaseService {
  private static instance: ChatService;

  static getInstance() {
    return (ChatService.instance ??= new ChatService());
  }

  async fetchPending(userId: string) {
    return this.executeQueryList<glyvio_entity.ChatSession>(
      `SELECT * FROM chat_session WHERE assigned_user_id = ? AND status = 'pending'`,
      [userId]
    );
  }
}
service.ts é Auto-Gerado
O arquivo plugin/environment/src/service.ts (SyncClient) é gerado pelo framework Glyvio. Nunca edite manualmente — as alterações serão sobrescritas. Use os métodos jeannieQueryList, jeannieQueryFirst, queryList, queryFirst, putIgnoreId e callTask a partir do BaseService.
Shared Commons Compartilhado shared/commons/src/

Exporta apenas constantes de identificação do plugin. Importado pelas três camadas via path alias @plugin/commons.

// shared/commons/src/index.ts
export const PLUGIN_ID   = 'glyvio-plugin-devena';
export const PLUGIN_NAME = 'Devena Plugin';
export const VERSION     = process.env.VERSION ?? '0.0.0';

Não coloque lógica de negócio aqui. Se precisar de uma constante em mais de uma camada, coloque em shared/commons. Se for só para server, use plugin/server/src/constants.ts.

Infraestrutura

O Manifesto (manifest.json)

O arquivo central que define o plugin para o runtime do Glyvio. Toda feature nova que adiciona entidades, permissões ou migrações passa obrigatoriamente por aqui.

Estrutura Principal

dependencies

Outros plugins que este depende: glyvio_core, crm, jeannie_v2, smtp, whatsappwpp, etc. Define quais @types ficam disponíveis.

permissions

Array de permissões que o plugin declara — views, tools, notificações. Precisa existir aqui antes de ser usado em qualquer camada.

dbVersions

Migrações incrementais do banco de dados. Cada nova versão define entidades novas, campos, chaves estrangeiras ou alterações. Nunca edite uma versão já existente.

// Estrutura de uma entidade em dbVersions
{
  "version": 3,
  "entities": [
    {
      "name": "erp",
      "fields": [
        { "name": "name", "type": "string", "required": true },
        { "name": "clientId", "type": "uuid", "foreignKey": "client" }
      ]
    }
  ]
}
Workflow com Manifesto
Após editar manifest.json, rode run_helper.sh na raiz do projeto. Ele regenera entity.d.ts, glyvio_structure.d.ts e o service.ts da camada environment. Sem isso, o TypeScript não enxerga os novos campos.
Infraestrutura

Registro e Descoberta Automática

Cada camada usa um mecanismo diferente de registro. Entender isso evita bugs silenciosos onde uma classe é escrita mas nunca carregada.

Camada Tipo Como é Registrado
App Rotas / Pages / Modals Registro explícito em index.ts via routerService.loadRoutes()
App Interceptors de App Registro explícito em index.ts via appInterceptorService.registerInterceptors()
App Menu items Registro explícito em index.ts via FullMenuPage.fullMenuGroupAdd()
Server Before / After / AfterCommit Interceptors Descoberta automática — Webpack varre src/interceptors/**/*.ts
Server Controllers Descoberta automática via decorador @Controller
Env SystemTool / CustomTool Descoberta automática via decorador @SystemTool / @CustomTool

Build & Release

Scripts do Monorepo

ComandoO que faz
pnpm buildInstall deps + build paralelo de app, server, environment
pnpm build:fastBuild sem install (mais rápido quando deps já estão instaladas)

./release_all.shRelease de todos os plugins (bump + commit + push)

Processo de Release com a Skill

Use a skill /release-project para automatizar o ciclo completo:

  1. Build de verificação
    Roda pnpm build para garantir que não há erros de compilação.
  2. Bump de versão
    Incrementa a versão patch no package.json (ex: 0.1.38 → 0.1.39).
  3. Commit automático
    Gera um commit descrevendo o que foi alterado com base no diff.
  4. Push para o remote
    Envia para a branch remota configurada. O CI/CD do GitHub Actions valida antes do deploy.
Antes do Release
Sempre rode pnpm lint antes. Erros de TypeScript que escapam do build podem causar comportamentos inesperados em produção. O build com isolatedModules: true não checa tipos — o lint é a barreira.

IA Assistida

Agentes Especializados

Além das skills, há agentes de IA especializados para tarefas mais complexas que envolvem múltiplos arquivos ou tomada de decisão arquitetural.

glyvio-app-coordinator
Use para trabalho completo de UI/UX no frontend: criação de páginas, modais e carts, decisão entre criar ou usar interceptor, registro de rotas e menus, e validação de tipos.
App
glyvio-app-chart
Especializado em criar e customizar gráficos: cartesiano (linha, barra, área), circular (pizza, rosca), funil e radial. Conhece o design API completo de seções, eixos, paleta e tooltips.
App
glyvio-server-coordinator
Para lógica de negócio server-side complexa: regras multi-entidade, interceptors encadeados, operações em transação, controllers e alterações no manifesto.
Server
glyvio-environment-agent
Para trabalho na camada de IA: @Action, @SystemTool, @CustomTool, queries com SyncClient, processamento de attachments, busca por similaridade fuzzy e gestão de secrets.
Env
glyvio-report-agent
Para dashboards HTML interativos servidos via SimpleController. Trabalha com Plotly.js, propõe layout de KPIs e gráficos a partir de queries SQL, gera preview antes de implementar.
Server
Plan
Arquiteto de software para planejar implementações complexas antes de escrever código. Use quando a feature afeta múltiplas camadas e há trade-offs a avaliar.
Qualquer
Quando usar agente vs. skill
Use uma skill quando sabe exatamente o que criar — ela gera o arquivo seguindo o padrão. Use um agente quando precisa de análise, decisões ou quando a tarefa afeta múltiplos arquivos e camadas ao mesmo tempo.
