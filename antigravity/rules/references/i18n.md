# Traduções (i18n) com parâmetros — ICU

> Parâmetros em `$T{…}` exigem um `glyvio_core` de 27/09/2026 ou mais novo (confira se
> `glyvio_core.t(key, params)` existe no `@types/glyvio_core.d.ts` do projeto).

As traduções ficam em `assets/i18n/<locale>.arb` (core e cada plugin). **Toda chave nova vai em
todos os idiomas** (pt_BR e en_US no mínimo).

Idiomas do app: `pt_BR`, `en_US`, `es_ES` e `fr_FR`. Um plugin sem o `.arb` do idioma do usuário
usa o `en_US` (e, sem ele, o `pt_BR`) — por isso o `en_US` é obrigatório. Para traduzir o plugin
de verdade, crie `es_ES.arb` e `fr_FR.arb` com as mesmas chaves e os mesmos `{parâmetros}`; o
`antigravity/scripts/i18n_check.mjs` confere chaves e parâmetros entre todos os arquivos.

## Chaves simples

```ts
title: '$T{crm_sidebar_client_title}'; // em designs (resolvido pelo interop)
glyvio_core.t('crm_sidebar_client_title'); // em código TS
```

## Chaves com parâmetros

```json
"crm_x_count": "{count, plural, =0{Nenhum registro} one{# registro} other{# registros}}",
"@crm_x_count": { "placeholders": { "count": { "type": "int" } } },
"crm_x_entering": "Entrando em {company}",
"crm_x_greeting": "{gender, select, female{Bem-vinda} other{Bem-vindo}}, {name}!"
```

- `plural`: `=N` exatos primeiro, depois `zero|one|two|few|many|other`; `#` é o número. Em pt-BR
  0 e 1 caem em `one`: use `=0{…}` quando o zero tiver texto próprio.
- `select`: ramo pelo valor, senão `other`.
- `''` = apóstrofo; `'{…}'` mantém chaves literais.

Passando valores:

```ts
// Em designs: lidos dos dados da tela, como $S
subtitle: '$T{crm_x_count count=state.totalCount}';
label: '$T{crm_x_greeting name=item.person.name gender=item.person.gender}';
label: '$T{crm_x_label n=3 prefix="Total"}';

// Em código TS (texto pronto)
glyvio_core.t('crm_x_entering', { company: company.name });
glyvio_core.translaterService.translate('crm_x_count', undefined, { count: rows.length });
```

## Regras

- **Nunca** monte frase concatenando pedaços (`` `${n} $T{…records}` ``); crie uma chave com
  parâmetros. Rótulo curto + valor (`` `$T{crm_user}: ${name}` `` num chip) é aceitável.
- Não coloque `$S{…}`, `{{…}}` nem caminhos de estado dentro do `.arb`. Mensagens antigas com
  `$S{param}` continuam funcionando (aparecem como `legacy`); ao mexer nelas, migre para `{param}`.
- Parâmetro faltando aparece como `{nome}`; mensagem malformada aparece crua. Nada lança erro —
  por isso rode a checagem.
- Evite gênero no texto quando não souber o da pessoa ("o usuário" genérico, ou `select`).

## Checagem (obrigatória após mexer em `.arb` ou `$T{}`)

```bash
node antigravity/scripts/i18n_check.mjs .                       # na raiz do plugin
node antigravity/scripts/i18n_check.mjs . --strict              # falha com código 1 (CI / release)
node antigravity/scripts/i18n_check.mjs . --extra ../outro-plugin/assets/i18n   # usa chaves de outro plugin
```

Chaves `core_*` (do próprio Glyvio) não são acusadas como faltando: o `.arb` do core não vem com
o plugin e elas são resolvidas em runtime. Use `--ignore-prefix <prefixo>` para ignorar outros.

Aponta chave usada sem tradução, chave faltando em um idioma, placeholders diferentes entre
idiomas, parâmetros passados que a mensagem não usa e `.arb` com código de template. `--strict`
faz falhar (CI).
